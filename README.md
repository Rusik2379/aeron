# АЭРОН

Исходники многостраничного сайта строительной компании и серверной панели управления. В текущем контенте — 6 статей и 22 объекта. Главная, услуги, портфолио, компания, новости, документы, контакты и отдельное направление девелопмента собираются из шаблонов.

## Запуск

Нужен Node.js 22 или новее. Выполните в папке проекта:

```sh
npm ci
npm run build
npm start
```

Сайт: http://127.0.0.1:4186/ . Админка: http://127.0.0.1:4186/admin/ . При первом локальном входе задайте собственный пароль от 12 символов. Общего пароля в репозитории нет.

После изменений исходников выполните `npm run build`. Изменения материалов через админку пересобирают страницы автоматически.

## Структура

- `build.mjs` — HTML-шаблоны и сборка страниц; `site.config.mjs` — общие параметры и значения по умолчанию.
- `content.mjs`, `articles.mjs`, `portfolio.mjs`, `portfolio-assets.mjs`, `client-projects.mjs` — направления, начальные материалы и фотографии.
- `about.mjs`, `business.mjs`, `development.mjs`, `geography.mjs`, `partners.mjs`, `legal.mjs` — специальные блоки, карта, клиенты и документы.
- `styles.css`, `business.css`, `portfolio.css`, `revisions.css`, `script.js` — актуальное оформление и поведение.
- `admin/`, `cms-server.mjs`, `content-store.mjs`, `mail.mjs`, `serve.mjs` — редактор, сервер, хранилище и обработчик заявок.
- `data/content.json` — текущие материалы и публичные настройки; именно этот файл редактирует CMS.
- `assets/` — актуальные изображения и логотипы. `docs/` — источники логотипов и описание генерации иллюстрации дома.
- `check-*.mjs`, `verify-seo.mjs` — проверки сборки, CMS, почтового обработчика и SEO.

HTML-страницы, `pages.json`, `robots.txt` и каталог `dist/` создаются сборкой. Они исключены из Git, чтобы не хранить дубли исходников. Перед запуском сервера на новом месте обязательно выполните сборку.

## Админка и данные

В редакторе доступны статьи, объекты с галереями, компания/заказчик, привязка к городу на карте, контакты, юридические реквизиты, количество объектов по городам и настройки SMTP. Черновики скрыты от посетителей.

Сервер создаёт `data/auth.json` (хеш пароля), `data/mail.json` (закрытые настройки почты) и `data/backups/`. Эти файлы не входят в репозиторий. Загруженные через CMS изображения сохраняются в `assets/uploads/`. Делайте отдельные резервные копии папок `data/` и `assets/uploads/` на сервере. Публичные изменения контента можно включать в Git отдельно; перед этим проверяйте содержимое `data/content.json`.

## Заявки на почту

Получатель заявок берётся из настройки e-mail компании; сейчас это `info@aeron.ru`. В админке → «Заявки на почту» подготовлены параметры VK WorkSpace: `smtp.mail.ru`, порт `465`, SSL/TLS. Для отправки нужно самостоятельно ввести пароль внешнего приложения и проверить подключение. Пароля почты в архиве нет. После подключения проверьте получение пробной заявки.

Альтернатива настройкам в админке — переменные окружения процесса `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_FROM`, `SMTP_PASSWORD`. Они имеют приоритет. Файлы `.env` автоматически не загружаются. Пароли не добавляйте в публичный JavaScript и Git.

## Размещение

Для сайта с админкой и отправкой заявок нужен Node-хостинг или VPS. Установите зависимости, соберите сайт и запустите `npm start` как постоянный процесс за HTTPS-прокси. `PORT` и `HOST` задают порт и интерфейс; по умолчанию — `4186` и `127.0.0.1`. `AERON_DATA_DIR` позволяет вынести хранилище за пределы проекта.

Укажите основной HTTPS-домен в настройках админки: он включает canonical, Open Graph и XML-карту сайта. Для защищённых cookie за HTTPS-прокси задайте `AERON_SECURE_COOKIES=1`; прокси должен сохранять исходный Host. Дополнительные разрешённые имена задаются через `AERON_ALLOWED_HOSTS` (через запятую).

`dist/` содержит статический вариант для обычного веб-хостинга. GitHub хранит исходники; статический GitHub Pages не запускает Node-сервер, админку и SMTP-обработчик.

## Проверки

```sh
npm run check
```

Проверки CMS и почты используют отдельные временные данные, не меняют рабочий пароль и не отправляют внешних писем.

## Изображения

Фотографии портфолио и визуализация промышленного фасада предоставлены заказчиком. Изображение коттеджа — концепция, созданная по его референсу, а не фотография выполненного объекта. В девелопменте используется актуальный логотип с зелёным домиком. Источники оригинальных логотипов компаний перечислены в `docs/client-logo-sources.md`. Фирменные знаки принадлежат соответствующим компаниям.
